# Hackathon Changelog

Every improvement made during the hackathon lands as its own commit so judges
can follow the progress with `git log`. The starting point and the full list of
known issues are documented in [docs/AUDIT.md](docs/AUDIT.md).

## Baseline (initial import)

- Imported the consent-first exam anti-cheat prototype (auth, exam delivery,
  integrity monitoring, desktop lockdown shell).
- Known at import: 1 failing test, 6 web typecheck errors, 4 critical bugs,
  2 performance issues and several unwired features.

## Hackathon progress

- **Fix #1** — phone status lookup queried a non-existent `integrity_phone_enrollments` table and crashed; now uses `phone_enrollments` (with regression test).
- **Fix #2** — vision bridge split stdout on a literal `\n` and wrote one to the Python server, so no request/response ever parsed; now uses real newlines and buffers partial lines.
- **Fix #3 (security)** — `PATCH /exam/attempts/:id/events` accepted unauthenticated requests, so anyone could inject fake app events for any attempt. It now requires a student session, CSRF token and attempt ownership; the Electron watcher forwards snapshots through the authenticated renderer instead of posting from the main process.
- **Fix #4 (security)** — the AI-check endpoint ran Gemini on any client-supplied text without checking attempt ownership. It now takes a `questionId`, verifies the attempt belongs to the caller and checks only their saved answer.
- **Security hardening (found during audit follow-up)** — liveness-verify, answer-revision history and recording upload routes did not check that the attempt belonged to the caller; all three now verify ownership.
- **Tests** — schema test still expected only the first three migrations; updated it to cover the integrity and phone presence tables (fixes the one failing test in the suite).
- **Green build** — fixed all 6 web typecheck errors: shared similarity report types moved into `@exam-anti-cheat/contracts`, `keystroke_violation` added as a flag-only violation type, a strict-index fix in the watermark encoder and a type declaration for the MediaPipe WASM factory. `npm run typecheck` and `npm test` (147 tests) now pass.
- **Kick policy** — the exam page had its own copy of the kick thresholds that omitted `overlay_detected`, so a Cluely-style overlay never kicked the student. Both the exam page and app shell now use the single `shouldKick` policy in `tabGuard.ts` (with tests).
- **Fix #5 (performance)** — Whisper allowed one transcription across all students and returned 503 to everyone else. It now runs a configurable pool (`WHISPER_CONCURRENCY`, default 2) with a bounded wait queue (`WHISPER_MAX_QUEUE`, default 8); only overflow is rejected.
- **Fix #6 (performance)** — overlapping vision requests silently rejected each other. The bridge is now a `VisionClient` with a FIFO queue, per-request timeouts, a bounded backlog and automatic restart when the Python server exits (with tests).
- **Fix #13** — `isExamPath()` omitted the recording, speedtest, vision, telemetry and transparency routes, so browser preflights got 404 and the calls failed cross-origin. All browser-called exam routes now pass preflight (with test).
- **Fix #9 / feature** — the web client already uploaded keystroke-dynamics telemetry every 15s, but no route handled it. `POST /exam/attempts/:id/telemetry` now stores validated, capped batches for in-progress attempts the caller owns.
- **Fix #10 / feature: Transparency report** — new `GET /exam/attempts/:id/transparency` (owner only) and a post-submission panel showing students exactly what monitoring recorded (displays, apps, flagged behaviour, vision, gaze, audio), labelled clearly as not a verdict.
- **Resilience** — without `GEMINI_API_KEYS` the whole integrity service was disabled, so events, telemetry, liveness, revisions and transparency all returned 404. Monitoring now always runs; only the Gemini-backed AI checks report that keys are missing.
- **Fix #8 / feature: Collusion detection API** — the Gemini-embedding similarity detector was never called. New instructor-only routes list published exams with free-text questions and run a similarity report over every student's saved answer, returning flagged pairs with student emails.
- **Fix #12 / feature: Instructor workspace** — instructors used to hit a dead-end screen, and the similarity dashboard showed hardcoded fake data. Instructors now get a workspace where they pick an exam question and run a live collusion check, with flagged pairs highlighted by student email. The demo seed now creates an instructor account.
- **Fix #7 / feature: Server vision** — the OWL-ViT/YOLO bridge was never called. `POST /exam/attempts/:id/vision-check` (enabled with `ENABLE_BACKEND_VISION=true`) runs a camera frame through the Python detector as a second opinion and logs phones, earbuds and smart glasses to the transparency report.
- **Feature: Desktop app monitoring end-to-end** — the Electron foreground-app/display watcher was never started by the web app. The exam page now starts it in the lockdown shell and forwards only meaningful changes (another app focused, extra display) through the authenticated events endpoint, so they appear in the transparency report.
- **Code quality** — `npm run lint` went from 66 errors to 0: dead variables and imports removed, `any` replaced with real types (validated liveness/phone API responses, typed transparency rows), and the `_unused` convention adopted in the ESLint config.
- **Formatting** — applied Prettier to the 60 files that had drifted (formatting only, no behavior change), so `npm run validate` (format + lint + typecheck + tests) passes end to end.
- **CI** — GitHub Actions runs `npm run validate` on every push and pull request.
- **Docs** — README rewritten around the consent-first story, demo accounts (student + instructor), optional features and the incremental commit trail.
- **Config** — the API and demo seed now load the gitignored `.env.local` (repo root or `apps/api/`) at startup; previously credentials only worked when exported in the shell.
- **Signed liveness challenges** — the unused `signNonce()` was a truncated SHA-256 hash, not an HMAC. Challenges are now signed with HMAC-SHA256 over attempt, nonce, type and expiry; the client echoes the signature and the server checks it in constant time before consuming the challenge, so forged, retyped or cross-attempt challenges are rejected without burning the real one.
- **Whisper setup** — `npm run setup:whisper` clones upstream whisper.cpp (pinned v1.9.5), builds `whisper-cli` and downloads the base model into the gitignored vendor folder. Verified end to end: the app's transcription pipeline turns a sample clip into text in about 3 s on CPU.
- **AI-written answer check (instructor)** — the AI check used to be a student-callable route that showed students their own AI score. It is now instructor-only: pick a question and Gemini scores every student's saved answer, quoting the phrases that look generated, colour-coded by likelihood and clearly marked when Gemini was unavailable. Both instructor panels share one question picker.
- **Server vision, working end to end** — `npm run setup:vision` builds the Python environment (pinned to torch 2.2.2 on Intel Macs, the last release with wheels there). The bridge now uses that venv and waits for the model's `READY` signal before sending or timing requests: OWL-ViT needs ~90 s on first download and ~8 s warm, so the old 20 s request timeout would have killed it in a restart loop. Verified live: overlapping requests during a cold load resolved in 10 s, warm requests in under 3 s.
- **Liveness check reachable** — the liveness modal existed but nothing ever opened it. A "Verify I'm here" button now starts a signed challenge during the exam; without the camera on it explains what to do instead of hanging, and finishing no longer skips the student to the next question.
- **License & demo script** — MIT license; README covers `setup:whisper`/`setup:vision`, `.env.local` loading and the new env vars; [docs/DEMO.md](docs/DEMO.md) is a 5-minute walkthrough for judges.
- **Gemini reliability (found in live rehearsal)** — similarity always returned 500 because the embedding model `gemini-embedding-exp-03-07` was retired (404 on every key); the default is now `gemini-embedding-001`. The client now retries 503 "high demand" and 500 errors (not just 429) with exponential backoff, really rotates to the next key on each retry (it used to reuse the same URL), sends keys in a header instead of the URL, and leaves room for thinking-model tokens.
- **Native webcam only for liveness** — the liveness check grabbed whatever `<video>` was on the page and sent a hard-coded brightness value, and the server read that value from the wrong field, so the flash check could never pass. Liveness now opens the camera through the physical-camera check (refusing OBS, Camo, DroidCam, iVCam, XSplit, mmhmm, NVIDIA Broadcast and other virtual sources from one shared blocklist), turns the screen white and measures the real brightness rise on the student's face — a looped video or virtual feed doesn't light up. The server independently rejects virtual or missing camera labels and records the camera used.
- **Disclosure** — [docs/EXISTING_CODE.md](docs/EXISTING_CODE.md) separates the pre-existing prototype (commit `1c94abb`) from hackathon work, lists third-party models and libraries, states known limitations, and gives ready-to-paste text for the submission's "Existing code and assets" field.
- **Honest consent copy** — the consent modal claimed the screen was "continuously recorded and uploaded to the cloud"; recording is actually opt-in and saved only to the student's computer. The AI-check and sign-in copy now match the consent-first design instead of "strict, continuously monitored" wording.
- **VM and capture-display detection** — the Electron preflight now refuses to start an exam inside a virtual machine (macOS hypervisor flag or VMware/Parallels/VirtualBox/UTM hardware model; Linux `systemd-detect-virt`/DMI) and asks the student to unplug capture or mirroring displays (Elgato, AVerMedia, Cam Link, Blackmagic…). During the exam, newly attached capture displays are reported to the transparency report. Detection failures never block.
- **Mid-exam camera guard** — if the webcam is unplugged, switched to a virtual source, or a virtual camera or HDMI capture device is attached during the exam, it is reported (once per device) to the transparency report. It watches only the long-lived camera-panel stream, so short liveness captures are never mistaken for an unplugged camera.
- **Local-first framing** — [docs/LOCAL_AI.md](docs/LOCAL_AI.md) inventories every AI component (where it runs, model, size, offline or not, how cloud parts degrade); the demo script now leads with on-device vision, liveness, Whisper and keystroke analysis, includes an optional pull-the-network moment, and presents Gemini instructor tools as secondary.
- **Demo data for instructors** — `npm run demo:seed` now adds four classmates with submitted answers (a near-copied pair, a templated AI-sounding answer, a casual human one), so the similarity and AI-written checks have something to show. Also fixed the seed's wipe step, which named tables that don't exist and silently did nothing.
- **Gemini fallback model** — during rehearsal `gemini-3.6-flash` kept answering 503 "high demand" even after retries; generation now falls back to `gemini-2.5-flash` (`GEMINI_FALLBACK_MODEL`) so exam generation and AI checks keep working.
- **Exam generation works live** — generating a 10-question exam hit the 30 s client timeout and then a 2048-token output cap (thinking tokens count against it), truncating the JSON. Timeout is now 90 s and the cap 8192; the demo seed now produces a real Gemini exam in under a minute.
- **Desktop setup** — newer npm skips install scripts, so the Electron binary was never downloaded and the lockdown shell couldn't start; `npm run setup:desktop` downloads it and builds the shell plus its native app-control helper.
- **Live-tested instructor review** — in rehearsal the fallback model `gemini-2.5-flash` turned out to be retired for new users (404). Generation now walks a fallback chain (`gemini-3.8-flash`, `gemini-3.5-flash`, configurable via `GEMINI_FALLBACK_MODELS`) past overloaded or retired models, and the AI-written check runs three answers in parallel instead of one at a time. Verified in the browser: similarity flagged the copied pair at 99.3%, and the AI check scored and quoted each classmate's answer.
- **Email templates** — six branded Supabase auth emails (confirm signup, reset password, change email, reauthentication code, instructor invite, magic link) in `supabase/templates/`, all linking to one `/account/confirm` page using the server-side `token_hash` flow; `npm run supabase:templates` applies them to the app's own Supabase project via the Management API.
- **Live link for judges** — `npm run share` starts the app and an ngrok tunnel on a static HTTPS domain (`SHARE_HOST`): the domain is added to the API's allowed origins and Vite's host allow-list (unknown hosts and origins are still refused), so judges can try it in a browser while all AI keeps running on the presenter's machine. HTTPS also satisfies the browser's secure-context rule for camera and microphone.
- **Auth emails via Microsoft Graph** — Supabase's free tier blocks custom templates on its built-in sender, so a new `auth-mailer` edge function implements the Send Email hook: it verifies the hook's Standard Webhooks signature, renders the committed templates (bundled by `npm run supabase:mailer-templates`), handles both halves of a secure email change, and sends through Microsoft Graph. Rendering is unit-tested.
- **Email account flows (Supabase)** — when `SUPABASE_URL`/`SUPABASE_ANON_KEY` are set, sign-up sends a confirmation email, "Forgot password?" sends a reset link (always 202, rate-limited, no account enumeration), and an Account panel offers change password and change email. Links land on `/account/confirm`, which verifies the token server-side; Supabase tokens never reach the browser and our session/CSRF boundary is unchanged. Without Supabase, local offline accounts work exactly as before. The demo seed pre-confirms demo accounts through the admin API so no emails go to fake addresses.
- **Adaptive cloud recording** — opt-in screen recording now measures upload speed first and picks 720p/15 fps, 540p/8 fps or 360p/5 fps so recording uses at most ~25% of the student's uplink. 10-second segments upload to the school's OneDrive one at a time in the background; if uploads fall behind, quality steps down, and after repeated failures it switches to saving locally — the exam UI never waits on an upload. Consent and status text explain all of this in plain language; the speed probe now requires a signed-in student. Test tooling now ignores agent worktrees.
- **iPhone desk camera** — the iPhone companion gains an opt-in "Desk camera": stood beside the laptop, its rear camera watches the desk and keyboard, and Apple's on-device Vision framework counts people and checks hands near the keyboard. Only three flags leave the phone (people, hands visible, framing OK) — never images — using the existing pairing credential. An extra person or leaving the frame becomes a lead in the transparency report (cooldown-limited); the exam's phone panel shows desk-camera status. Also fixed the companion's two Xcode warnings (orientation, deprecated `onChange`); `xcodegen` regenerates the project from `apps/ios/project.yml`.
- **Liveness students can always pass** — the default check is now a passive random colour flash: the screen shows three random colours and the native webcam must see the student's face reflect them in order (scored relative to each student's own baseline, so it is fair across skin tones and lighting; the sequence is HMAC-signed). If the room is too bright, a head-turn check (left/right via on-device MediaPipe) is offered, and "I can't do the visual check" lets a student say three words checked by local Whisper. The hand-gesture challenge — hardest for students and dependent on downloading model weights at runtime — is gone, along with the TensorFlow dependencies.
- **Account-flow hardening (from an independent security review)** — password reset/change now signs out other sessions; sign-up and forgot-password are limited per client, per email and globally so nobody can use the school's mailbox to spam an address; sign-up no longer reveals whether an account exists; password guesses are throttled on login, change-password and change-email; changing to an email already in use is refused before Supabase is touched; a password-reset link now gives a reset-only session; Supabase calls time out after 10 s; the service-role key is no longer loaded by the running server; rate-limit memory is bounded; the demo seed refuses to touch non-demo accounts; and the email renderer fills placeholders in a single pass.
- **Docs refresh** — README, a 5–7 minute demo script (labels verified against the UI) and the hackathon highlights now cover accounts, adaptive recording, the new liveness checks, device rules and the iPhone desk camera; the third-party list now reflects the removal of TensorFlow.js.
- **iPhone reliability** — a brief Wi-Fi drop during pairing no longer throws away the QR pairing (it retries with backoff and only asks for a re-scan on a real rejection); the heartbeat now ticks on a fixed 2 s schedule instead of drifting with network latency; one stray rejection gets a retry before unpairing; and the screen stays awake while reconnecting. Decision logic is pure Swift with unit tests.
- **Liveness storage** — migration 0007 widens the challenge-type check so colour-flash, head-turn and spoken-word challenges are stored under their real names; older rows still read correctly.
- **Phone presence fixes (review)** — a failed status poll no longer blocks answering for students who never paired a phone (and paired phones get three strikes, not one); the phone modal is keyboard-accessible (Escape, focus trap, focus restore); desk-camera state is pruned so memory stays bounded; the iOS camera cleans up after a failed setup and reports on the main actor.
- **iPhone XR and newer** — the companion targets iOS 16 (the XR's line ends at iOS 18) and iPhone only, every API was audited against that target, the desk camera uses a light 640×480 feed so A12 phones stay cool, and the Local Network permission and supported-device/install notes are documented. Device and simulator builds have zero warnings.
- **Recording fixes (review)** — per-attempt segment and size quotas, a per-student upload rate limit, no overwriting of stored segments (also enforced at OneDrive), WebM content check, uploads only while the attempt is in progress, and storage errors never leak to the browser. On the client, a hung upload times out after 15 s, the backlog is capped, a short Wi-Fi blip no longer ends cloud recording for the whole exam (it re-probes and resumes), throughput is estimated from real uploads instead of extra probes, and local fallback downloads are spaced so the browser doesn't block them.
- **Liveness fixes (review)** — the check can never get stuck (timeouts, an always-visible Close, Escape, focus trap), answering really pauses while it runs, the result is shown honestly ("Presence check passed" or "Not verified — you can try again"), colour-flash and head-turn passes are labelled client-measured, reduced-motion users get the head-turn check by default, challenge requests are rate-limited, and opening the check no longer counts as leaving the exam window.
- **One-command start** — `npm run doctor` checks Node, npm, free ports and optional tools with exact fix commands; `npm run demo` installs only when needed, prepares vision models, offers to build Whisper, creates a blank `.env.local` if missing, seeds once (`--reset` backs up first), starts everything, prints all demo accounts and opens the browser; Ctrl+C stops every process cleanly.
- **Disclosure** — `docs/EXISTING_CODE.md` now names the AI development tools used during the hackathon (Claude Code), as the submission rules require.
- **Docker** — `docker compose up --build` serves the web app and API together on http://localhost:8080 (the API now serves the built web app with the same security headers, SPA fallback and immutable asset caching), with local Whisper transcription built in, demo data seeded on first start, a persistent database volume and a health check. Server-side OWL-ViT is an optional profile.
- **Checks start themselves** — once a student has agreed on the consent screen and granted camera and microphone, the camera checks start as the exam opens and audio checks a second later; both can still be stopped from the sidebar and a failed start never retries in a loop. Liveness (flashing colours) and browser screen recording stay user-initiated; in the desktop app, starting recording picks the primary screen without a picker.
- **Pitch and submission** — the demo script is now a timed 4:45 run for the 5-minute slot, with a pre-stage checklist, a bad-Wi-Fi plan and honest answers to likely judge questions; `docs/SUBMISSION.md` has ready-to-paste answers for every required field (what runs locally, what needs internet, models, frameworks, APIs, existing code, AI tools, why local) plus a 60-second video shot list.
- **Wearables second opinion** — the browser model only knows COCO's 80 everyday classes (phones yes; earbuds, glasses and watches no), so when local server vision is enabled the camera panel now sends one downscaled frame every ~20 s (never overlapping) to OWL-ViT, which also looks for earbuds, headphones, headsets, smart glasses and smartwatches. Results show in the panel and, as medium-severity leads, in the transparency report; checks that aren't available say "not checked" instead of failing. The vision route is rate-limited and size-capped.
- **Judge demo mode (desktop)** — the desktop app now defaults to a demo mode that is safe on a judge's own Mac: the pre-exam check still lists other apps, extra displays, virtual machines and capture displays, but offers "Continue (demo mode)" instead of blocking, and never quits or force-quits anything; a small banner says so. Strict mode (from the Mode menu, with confirmation) behaves as before and no longer has the built-in development exemptions. The setting is stored per user with owner-only permissions.
- **Live transcript** — while audio checks run, the panel shows a blinking ● REC indicator and a live microphone level meter (static under reduced motion), and Whisper's text appears as a timestamped rolling log every ~3 s, with a "transcribing…" line while a clip is processing. Transcripts (text only, never audio) are saved per attempt, restored after a reload, and shown to the student in a "What was heard" section of the transparency report.
- **Desktop app runs everything itself** — the API is bundled into one file and the Electron app starts it in a background utility process (with a fallback), serving the built web app and API on 127.0.0.1 so no dev servers are needed. Data and logs live in the user's Application Support folder, demo data is seeded once, a busy port or crash shows a clear dialog, and the server stops cleanly on quit. `npm run dev` in apps/desktop still uses the Vite dev server.
- **Desktop sign-in works** — Electron's built-in Node lacks native Argon2, so the packaged app failed at the first login or seed. Password hashing now falls back to a WebAssembly Argon2id (`hash-wasm`) with identical parameters and hash format, so hashes from either verify with the other (measured ~70 ms vs ~37 ms native per hash). Verified: the bundled API seeds and signs in under Electron's own Node.
- **Mac installer** — `npm run package:mac` builds an Intel `.dmg` (~144 MB) of the desktop app with the API, web app and native helper bundled, ad-hoc signed and verified after packaging (minimum macOS 13; runs on Apple silicon through Rosetta 2). Verified: the packaged app serves the web app and API on 127.0.0.1. [docs/JUDGES.md](docs/JUDGES.md) explains install, the unsigned-app Gatekeeper step, permissions and demo accounts. Transcription is not bundled yet.
- **Server vision with several students** — frames are now sent to OWL-ViT one at a time (each request's timeout starts when it is actually sent), so queued students no longer time out and force a model restart; a crashed Python process fails the request cleanly instead of crashing the API, and the vision process stops with the server.
- **Transcription consent and retention** — the consent screen now says plainly that short audio clips are transcribed to text on this computer by Whisper, that only text is kept (never audio), that the student sees it in their report, that it is deleted after 30 days by default (`AUDIO_RETAIN_DAYS`), and that nearby voices can be captured. Old transcripts are swept on start, daily and on read. A failing sound meter no longer stops transcription.
- **Desktop hardening (review)** — Demo mode is now an explicit judge-build default (`npm run package:mac` builds the judge DMG); every other build defaults to Strict, and a missing or corrupt settings file falls back to the build's default rather than to Demo. Switching mode in either direction needs confirmation, and a demo-mode session is reported in the transparency report. An AI coding app is no longer exempt in Strict mode. Demo accounts are seeded only in the judge build, in the background, never re-wiping on retry. Also: startup errors are caught, pop-up windows are denied, only camera/mic/screen permissions are granted and only to the app's own page, IPC handlers check the caller, the local proxy checks the Host header and times out, and the app watcher no longer blocks the main thread.
- **iPhone companion polish** — tested on an iPhone SE simulator and on a real iPhone XR (iOS 18.3.2): the keyboard now dismisses after pasting a pairing link so the status message is visible, a bad link shows a plain-language message instead of developer jargon, and four XCUITest UI tests cover launch, invalid and unreachable links, and the camera-unavailable state.
